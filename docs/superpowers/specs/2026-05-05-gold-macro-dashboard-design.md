# 黄金宏观分析台设计文档

> 日期：2026-05-05
> 状态：已确认设计，待用户复核
> 对应需求来源：[四象限.md](/D:/note/pandas_project/gold_price_analysis/四象限.md)

## 1. 目标

为当前仓库新增一个独立的中文可视化网页，用于观察黄金与美元、利率、信用利差、股指之间的联动关系，并把用户在 [四象限.md](/D:/note/pandas_project/gold_price_analysis/四象限.md) 中定义的判断逻辑落成一个可交互的分析台。

这个页面的定位不是通用网站，而是：

- 自用优先的日常分析台
- 同时保留足够的展示感，适合向他人解释分析逻辑

## 2. 交付范围

本次交付包含三部分：

1. 一个独立的静态可视化页面
2. 一个前端消费用的数据整理产物
3. 对 [四象限.md](/D:/note/pandas_project/gold_price_analysis/四象限.md) 的补充说明和页面入口

本次不做：

- 后端服务
- 数据在线拉取
- 用户登录、存档、多页面导航
- 通用指标配置系统

## 3. 用户体验目标

用户打开页面后，应该在 5 秒内完成三件事：

1. 看见当前的综合入场判断是 `预测 / 确认 / 错配` 中哪一种
2. 快速确认黄金、美元、利率、信用四条主线是否共振
3. 通过四象限知道当前宏观位置落在哪个区间

页面语言全部使用中文，不保留英文界面文案。

## 4. 设计方向

页面采用已确认的 `B` 方向，即“展示感更强”的金融科技风格页面，但内部信息组织仍然服务于自用分析效率。

### 4.1 视觉原则

- 深色背景，避免泛白分析页风格
- 冷蓝色作为页面骨架与信息框主色
- 金色只用于黄金和关键确认状态，不滥用
- 文字全部中文，避免中英混排导致气质不统一
- 层级明确，首屏先给结论，再给图，再给信号细目

### 4.2 页面结构

首页从上到下分为五层：

1. 顶部大结论区
2. 三张主图 + 四象限区
3. 信号判断清单
4. 详细指标走势区
5. 文档入口或简短说明区

## 5. 页面信息架构

### 5.1 顶部大结论区

职责：直接给出当前筛选时间窗下的入场类型与摘要结论。

包含内容：

- 页面标题：`黄金 / 美元 / 利率 信号矩阵`
- 全局日期筛选器：开始日期、结束日期
- 当前入场类型：`预测 / 确认 / 错配`
- 结论摘要：用一句中文解释为什么得到这个判断
- 3 个关键状态卡片：黄金、DXY、TIPS 的当前方向

### 5.2 三张主图

职责：先看资产价格，不先扎进底层因子。

三张图分别为：

- 黄金价格走势：使用 `XAU/USD日线OHLC`
- 标普500价格走势：使用 `SP500`
- 纳斯达克100价格走势：使用 `NASDAQ100`

首版主图优先展示收盘价格走势，不在首版里加入复杂技术指标。

### 5.3 四象限区

职责：把当前宏观状态投影到用户定义的 `DXY × TIPS` 框架中。

规则：

- 横轴：`DXY`
  - 左侧表示下降
  - 右侧表示上升
- 纵轴：`TIPS`
  - 上侧表示上升
  - 下侧表示下降

四象限固定文案：

- 左上：`再分配区，债券弱，黄金弱，股票可涨但不稳`
- 右上：`股票下跌风险高，黄金弱，债券弱（流动性紧缩，美元走强）`
- 左下：`股票涨，黄金走强，债券走强（全面宽松）`
- 右下：`股票不稳，黄金中性，债券走强（避险资金流入美元）`

页面用五角星标记当前所在象限。

### 5.4 信号判断清单

职责：把文档里的逻辑条件显式展开，不让用户猜结论是怎么算的。

显示项：

1. `10年期TIPS实际收益率`：上升 / 下降 / 横盘
2. `DXY`：上升 / 下降 / 横盘
3. `10年期美债收益率`：上升 / 下降 / 横盘
4. `10年盈亏平衡通胀率`：上升 / 下降 / 横盘
5. `黄金价格是否上涨`：是 / 否
6. `高收益信用利差是否收窄`：是 / 否
7. `10年期美债收益率是否下降`：是 / 否
8. `入场类型`：预测 / 确认 / 错配

### 5.5 详细指标走势区

职责：让用户在结论之后继续下钻。

图表列表：

- 10年期TIPS实际收益率
- DXY
- 10年期美债收益率
- 10年盈亏平衡通胀率
- 高收益信用利差_OAS
- SOFR

## 7. 技术方案

### 7.1 页面产物

采用独立静态页面：

- `HTML`
- `CSS`
- 原生 `JavaScript`

不引入前端框架。

原因：

- 当前需求是单页分析台，不需要框架级复杂性
- 更容易完全掌控视觉风格
- 更适合仓库当前以数据脚本为主的结构
- 便于直接从 Markdown 文档跳转使用

### 7.2 数据进入前端的方式

页面不直接在浏览器里散读多个 CSV。

改为增加一个轻量的数据整理步骤，把需要的指标汇总为一个前端专用 `JSON` 文件。前端只消费这个 JSON。

这样做的原因：

- 前端数据入口统一
- 便于先在整理步骤中完成字段标准化
- 可在整理阶段完成日期对齐、空值处理、基础派生
- 减少页面端对 CSV 格式差异的适配逻辑

### 7.3 建议文件布局

建议新增：

- `visuals/gold_macro_dashboard/index.html`
- `visuals/gold_macro_dashboard/styles.css`
- `visuals/gold_macro_dashboard/app.js`
- `visuals/gold_macro_dashboard/data/dashboard_data.json`
- `scripts/build_gold_macro_dashboard_data.py`

如果实现阶段发现更贴合仓库结构的目录命名，可做小幅调整，但必须满足：

- 页面和数据文件相邻可部署
- 脚本与页面职责分离
- 文档可稳定链接到页面入口

## 8. 数据整理规则

### 8.1 统一时间字段

所有序列统一转为 `date` 字段，并按升序排列。

### 8.2 主图价格序列

- 黄金主图优先使用 `OHLC` 中的收盘价
- 标普500与纳指100使用各自可用的收盘值

### 8.3 日期筛选

前端提供一个全局开始日期和结束日期。

筛选规则：

- 所有图表只展示筛选区间内的数据
- 所有信号判断只基于筛选区间内的数据
- 若某个指标在筛选区间内无有效数据，页面必须显式提示缺失，而不是静默输出错误结论

### 8.4 对齐策略

不同指标的频率可能不同，但本页主要使用日频数据；若存在节假日或个别缺口：

- 趋势判断以筛选区间内该指标的首个有效点和最后一个有效点为准
- 不强制所有序列逐日完全对齐后再判断
- 四象限与信号判断使用各自序列的有效起止点

## 9. 信号判断规则

### 9.1 趋势三分类

以下指标输出 `上升 / 下降 / 横盘`：

- 10年期TIPS实际收益率
- DXY
- 10年期美债收益率
- 10年盈亏平衡通胀率

首版规则：

- 若区间终值高于起值，判定为 `上升`
- 若区间终值低于起值，判定为 `下降`
- 若终值与起值近似相等，判定为 `横盘`

实现阶段必须为“近似相等”设定一个明确阈值，并把阈值写进代码注释或文档说明。

### 9.2 二元确认信号

输出 `是 / 否` 的项目：

- 黄金价格是否上涨
  - 条件：黄金区间终值 > 起值
- 高收益信用利差是否收窄
  - 条件：高收益信用利差区间终值 < 起值
- 10年期美债收益率是否下降
  - 条件：10年期美债收益率区间终值 < 起值

### 9.3 入场类型

#### 预测

当 `TIPS` 与 `DXY` 开始出现下降拐点，但未完全确认时，判定为 `预测`。

首版为避免过度复杂，`开始出现下降拐点` 需要在实现阶段做一个保守、可解释的近似规则，例如：

- 最近一段子区间内从上升转为下降
- 或短周期变化方向已转负，但确认信号数不够

此规则在实现时必须固定为单一定义，不能保留模糊描述。

#### 确认

同时满足以下条件时判定为 `确认`：

1. `TIPS` 下降
2. `DXY` 下降
3. `10年期美债收益率` 不上升
4. 下列三项中至少两项为真
   - 黄金价格上涨
   - 高收益信用利差收窄
   - 10年期美债收益率下降

#### 错配

出现确认信号之后，如果风险资产表现与预期结构不一致，则判定为 `错配`。

由于用户原始描述里“错配”的完整判定句没有完全写清，首版设计要求实现阶段采用一个明确、可解释的代理规则，并在代码中注明。例如：

- 已满足确认条件，但标普500明显走弱

此处在进入实现计划前，需要把“明显走弱”的阈值写死，不能保留模糊语言。

## 10. 四象限定位规则

页面以当前筛选区间内 `DXY` 与 `TIPS` 的净变化方向决定所在象限：

- DXY 下降 + TIPS 上升：左上
- DXY 上升 + TIPS 上升：右上
- DXY 下降 + TIPS 下降：左下
- DXY 上升 + TIPS 下降：右下

如果某一轴为 `横盘`，实现阶段需要定义一个稳定的回退策略，例如：

- 归入离零最近的主方向
- 或单独显示“边界状态”

首版推荐显示为“边界状态”，避免硬塞入某一象限造成误导。

## 13. 风险与边界

### 13.1 规则歧义

当前最需要在实现阶段固定的两处是：

- `预测` 的拐点判定
- `错配` 的具体阈值

这两个点不能在实现中保持自然语言模糊。

### 13.2 数据频率与缺口

不同数据源可能存在非交易日缺失或更新节奏不齐，页面必须对缺失做显式处理，不得默认补值导致错误判断。

### 13.3 页面角色边界

这个页面是分析面板，不是研究报告生成器；首版不加入自动长文本解释，不把页面做成内容门户。

## 14. 实施建议

建议实现顺序：

1. 先完成数据整理脚本与前端 JSON 结构
2. 再完成页面静态布局与视觉系统
3. 然后接入日期筛选与图表
4. 最后实现信号判断、四象限逻辑与文档集成

这样可以先把数据和视觉边界稳定下来，再上规则逻辑，避免返工。
