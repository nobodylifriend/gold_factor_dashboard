# 黄金宏观 Dashboard 多 Tab 扩展设计
> 日期：2026-05-10
> 状态：提案
> 适用范围：`visuals/gold_macro_dashboard`

## 1. 设计判断

当前 dashboard 的问题不是信息太少，而是信息入口只有一个。

现在的页面适合回答一个问题：

- 当前黄金 / 美元 / 实际利率这组三角关系，处在什么状态

但项目里的指标已经明显超出这个范围，后续如果继续把所有图堆进同一页，会有三个直接问题：

1. 首屏判断会被大量细节稀释
2. 不同频率、不同语义的指标会混在一起
3. 用户会从“判断页面”被迫切换成“找图页面”

所以这次扩展不建议做成“一个更长的单页”，而是升级成：

- `总览` 负责给结论
- `专题 Tab` 负责给证据

也就是说，首页是指挥台，Tab 是工作台。

## 2. 总体结构

建议把当前 dashboard 扩成 7 个一级 Tab：

1. `总览`
2. `黄金本体`
3. `利率 / 流动性`
4. `通胀 / 通胀预期`
5. `美元 / 汇率`
6. `风险偏好 / 信用`
7. `财政 / 债务`

如果后续 `央行购金 / ETF 持仓 / COT / 期权` 数据继续扩充，再单独拆出第 8 个 Tab：

8. `持仓 / 衍生品`

不建议一开始就做成 10+ 个 Tab。一级导航过多会把“分析框架”变成“指标仓库”。

## 3. Tab 角色定义

### 3.1 总览

保留现有页面的核心地位，但做轻量重构。

保留内容：

- 当前结论 Hero
- 日期筛选
- 黄金 / 标普 / 纳指主图
- `DXY x TIPS` 四象限
- 当前信号矩阵

新增内容：

- 顶部一级 Tab 导航
- `本次结论由哪些专题支持` 的专题摘要条
- 每个专题只展示 1 到 2 个代表性卡片，不在总览塞完整图墙

定位：

- 3 秒读结论
- 10 秒知道该点进哪个专题继续看

### 3.2 黄金本体

这是“黄金自己在发生什么”，不再只当成结果变量。

建议容纳的指标：

- `XAU/USD 日线`
- `XAU/USD 月线`
- `GVZ`
- `GLD Total Holdings`
- `GLD Share Volume`
- `Global Gold ETF Holdings`
- `Global Gold ETF Net Flows`
- `Official Gold Reserves`
- `Change in Official Gold Reserves`
- `Global Gold Mine Production`
- `Global Gold AISC`

页面结构建议：

- 顶部摘要：价格趋势 / 波动率 / ETF 资金 / 央行购金
- 中部两列图墙：价格与波动、资金流与持仓、供给与成本
- 底部一句解释区：把“价格上涨是风险驱动还是配置驱动”写出来

### 3.3 利率 / 流动性

这是目前总览的核心驱动页，应当是第二重要的页。

建议容纳的指标：

- `10Y TIPS`
- `5Y TIPS`
- `30Y TIPS`
- `10Y Treasury`
- `3M Treasury`
- `SOFR`
- `Fed Funds`
- `M1`
- `M2`
- `货币基础`

页面结构建议：

- 顶部拆成三个信号盒：`实际利率` / `名义利率` / `短端流动性`
- 中部优先做“期限层级”展示，而不是把所有利率平铺
- 底部补一个“黄金对真实利率敏感，对短端政策利率滞后”的解释文案

### 3.4 通胀 / 通胀预期

这页不要变成统计局指标大全，而是围绕“黄金在交易哪一种通胀”。

建议容纳的指标：

- `CPI`
- `核心 CPI`
- `PCE`
- `核心 PCE`
- `PPI`
- `GDP 平减指数`
- `10Y Breakeven`
- `5Y Breakeven`
- `5Y5Y Forward Inflation`
- `10Y 名义减实际`
- `密歇根大学 1 年通胀预期`
- `SPF 通胀预期`

页面结构建议：

- 第一行：市场定价的通胀预期
- 第二行：实际公布的通胀数据
- 第三行：居民 / 调查预期

不要按“同比 / 环比 / 年化”各自分块；那是数据口径，不是分析逻辑。
应该按：

- 市场预期
- 已实现通胀
- 预期分歧

来组织。

### 3.5 美元 / 汇率

当前总览里美元只有一个 `DXY`，这对专题层明显不够。

建议容纳的指标：

- `DXY`
- `Broad Dollar Index`
- `EURUSD`
- `USDJPY`
- `USDCHF`
- `USDCAD`
- `AUDUSD`
- `GBPUSD`

页面结构建议：

- 顶部先给“美元强弱总判断”
- 中部左侧放广义美元与 DXY
- 中部右侧放主要货币对热力卡片
- 底部给“美元上涨是避险、增长、还是利差驱动”的简短标签

这页最好做成“主指数 + 货币篮子”，而不是 8 张一模一样的小折线图。

### 3.6 风险偏好 / 信用

这是用来确认黄金上涨到底是“宽松友好”还是“风险防御”。

建议容纳的指标：

- `SP500`
- `NASDAQ100`
- `VIX`
- `VIX9D`
- `VIX3M`
- `VIX6M`
- `VIX1Y`
- `VVIX`
- `VXN`
- `SKEW`
- `High Yield OAS`
- `Investment Grade OAS`
- `TED Spread`
- `STLFSI4`
- `Copper`
- `WTI`
- `Brent`

页面结构建议：

- 第一行：股指与信用利差
- 第二行：波动率期限结构
- 第三行：金融压力与顺周期商品

这里最重要的不是图多，而是要让用户一眼看出：

- 风险资产是否在确认
- 信用是否在恶化
- 波动率是否只是短端冲击

### 3.7 财政 / 债务

这是偏中长期叙事页，频率低，但在黄金的大级别配置逻辑里很重要。

建议容纳的指标：

- `Total Federal Debt`
- `Total Federal Debt to GDP`
- `Federal Debt Held by Public`
- `Federal Debt Held by Public to GDP`
- `Federal Interest Payments`
- `Federal Interest Payments to GDP`
- `Federal Interest Payments to Receipts`
- `Federal Surplus or Deficit`
- `Federal Surplus or Deficit to GDP`
- `Federal Current Receipts`
- `Average Interest Rate on Total Interest-Bearing Debt`
- `Marketable Treasury Securities Outstanding`
- `Treasury Net Marketable Borrowing Estimate`
- `Nominal GDP`

页面结构建议：

- 顶部先给“债务压力是否结构性上升”
- 中部看债务存量与利息负担
- 底部看融资需求与赤字压力

这页适合低频、长期尺度，不建议默认跟总览一样使用短窗口。

## 4. 统一页面骨架

为了避免每个 Tab 变成另一套页面，建议所有专题页统一成同一骨架：

1. `专题头部`
2. `信号摘要条`
3. `主图区`
4. `辅助图区`
5. `解释 / 注释区`

具体到 UI：

- `专题头部`：标题、当前结论、口径说明、最近更新时间
- `信号摘要条`：4 个以内高价值结论卡，不要做成十几个小 badge
- `主图区`：2 张最重要的大图
- `辅助图区`：2 到 6 张次级图，允许两列网格
- `解释区`：用中文写清“这页到底说明什么”

## 5. 导航设计

一级 Tab 建议放在 Hero 下方，做成横向可滚动的 sticky 导航条。

导航文案不要写成纯数据分类，建议写成“分析意图 + 数据群”：

- `总览`
- `黄金本体`
- `利率流动性`
- `通胀预期`
- `美元汇率`
- `风险信用`
- `财政债务`

每个 Tab 标签下方可加一行极短副标题，例如：

- `总览`：当前判断
- `黄金本体`：价格与资金
- `利率流动性`：真实利率主线
- `通胀预期`：预期与兑现

这样导航不是目录，而是分析地图。

## 6. 总览页与专题页的关系

一个关键约束：

不要在每个 Tab 都重复做一遍总览 Hero。

建议层级如下：

- `总览页` 给最终判断
- `专题页` 给局部判断

例如在 `利率 / 流动性` Tab 中，只需要显示：

- 本专题结论：`实际利率回落，对黄金偏多`

而不是再显示整套 `预测 / 确认 / 错配` 入口状态。

否则用户每切一个 Tab 都要重新理解“这里的结论是全局还是局部”。

## 7. 视觉策略

当前页面的深色金融科技风格可以保留，但需要从“单页展示感”升级成“系统感”。

建议保留：

- 深色底
- 蓝金双主色
- 玻璃感面板

建议新增：

- Tab 激活态有更明确的金色底线或填充
- 每个专题使用自己的辅助色，但不要改整体主题
- 图表卡片增加 `主图 / 辅图` 两种层级尺寸
- 页面内加入更清晰的分隔标题，例如 `价格`, `资金`, `波动`, `供给`

不建议：

- 每个 Tab 换一套大色盘
- 每个专题都做复杂插画背景
- 为了“丰富”而加过多说明性文案

这是分析工具，不是品牌官网。

## 8. 实现建议

现有代码结构适合做成“单页应用内多视图”，不需要拆成 7 个 HTML。

建议实现方式：

1. `index.html` 新增一级 Tab 容器和专题内容容器
2. `dashboard_data.json` 增加 `tabs` 配置与指标分组元数据
3. `app.js` 从“写死一组图”改成“按 tab schema 渲染”
4. `styles.css` 增加 sticky tab rail、专题头部、分组标题、图卡尺寸系统

建议的数据结构方向：

```json
{
  "metadata": {
    "tabs": [
      {
        "id": "overview",
        "label": "总览",
        "description": "当前判断"
      },
      {
        "id": "gold",
        "label": "黄金本体",
        "description": "价格与资金"
      }
    ]
  },
  "tabLayouts": {
    "gold": {
      "summarySeries": ["xau", "gvz", "gld_holdings", "gold_etf_flows"],
      "mainCharts": ["xau", "gvz"],
      "secondaryCharts": ["gld_holdings", "gold_etf_flows", "official_gold_reserves"]
    }
  }
}
```

核心思路是：

- 图表组件复用
- 布局配置化
- 结论文案按 tab 单独生成

## 9. 推荐的第一阶段落地范围

第一阶段不要一次把所有指标都接进前端。

建议先做 4 个 Tab：

1. `总览`
2. `黄金本体`
3. `利率 / 流动性`
4. `通胀 / 通胀预期`

原因很简单：

- 这四页已经能形成黄金分析的主闭环
- 现有数据基础最完整
- 可以先验证多 Tab 交互和信息密度是否合适

第二阶段再补：

5. `美元 / 汇率`
6. `风险偏好 / 信用`
7. `财政 / 债务`

## 10. 最终建议

这次扩展最重要的不是“把更多指标放进去”，而是明确每个页面在回答什么问题。

我建议把整个 dashboard 的产品定义改成：

- `总览页`：黄金宏观判断入口
- `专题页`：驱动拆解与证据浏览

这样做之后，页面不会因为指标增加而失控，后面继续加 `央行购金`、`期权偏斜`、`COT`、`财政融资` 也还有清晰位置。
